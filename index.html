War of the Visions: Final Fantasy Brave Exvius

Interned ahead of the game's global release, analyzing its data structures and codebase. Developed VBA-based visualization tools for data versioning that stayed in use for the rest of the project's lifespan.

Tutorial flow document

First task on entering Gumi Asia.

Goals

  • Create a document for visualizing the entire tutorial
  • Document used to petition for reducing the tutorial length for global release

Obstacles

  • Existing tutorial was quite lengthy (500+ shots)
  • No access to tools like Adobe Photoshop with batch automation

Results

  • Created two tools using Unity C#
    • First tool took a high-quality screenshot on hotkey press, significantly reducing the time needed to slowly snip the screen
    • Second tool went through all photos in a folder, placed them in an ordered structure, then took a screenshot
  • Inclusive of tool creation time, the task was completed within 3 working days, compared to the original allocation of 10 working days
  • Also completed the extended goal of digging out attached analytics trackers within the week

Data versioning compare tool

Made VBA-built comparison tool for versioning the game's data

Goals

  • Create a tool that could more clearly visualize differences between data versions
    • Previously this was done using the diff tool on source management
  • Make it easier to document version to version differences

Results

  • Quickly picked up VBA programming for Excel for tool creation
  • Created an Excel tool that would show changes in context of the data column; the tool did the following:
    • Showed value changes as "[old value] → [new value]", highlighting the changed cells
    • Highlighted added and removed data rows
    • Created a change summary showing:
      • How many values changed
      • Number of added/removed rows
      • Any added/removed columns
  • Further extended the tool to work for all data files, allowing a single button click to run comparison for all files

Global ad gacha feature

Ad summon feature geared towards global players

Goals

  • Craft a Video Summon feature to drive revenue from the global audience, which is less prone to spending than Japan
  • Drive engagement on ad features

Obstacles

  • Issuance of Visiore (game currency) very restricted, limiting the draw of the Video Summon
  • Concerns on technical feasibility from backend engineers

Results

  • Focused Video Summon on progress materials, with Visiore as a "bonus"
  • Created a cumulative reward structure to incentivize reuse
    • Intermediate states to act as "progress steps" along the way
  • Resolved engineer concerns, going through how data would be set up and exported to JSON

Dissidia Final Fantasy Opera Omnia

Working on a Live Ops title, usual responsibilities include maintaining regular content updates, running staging checks.

Looking to improve the processes, I went into optimization and automation, cutting out unnecessary steps and using tools to cut manual entry.

Settings menu rework

  • Settings menu was designed in a non-scalable way, and a rework was needed for new features
  • Proposed rework of settings menu screen to accommodate for future options added

Colorblind mode

Colorblind research and proposal following a QOL suggestion by the Design Lead

Goals

  • Create a QOL feature which makes the game more accessible for colorblind users

Results

  • Used Photoshop filters to visualize what a colorblind user might see
    • From there, identified issues with the game UI
      • The game uses a lot of blues and bluish-greens, which meant a lot of those accents were lost on blue-blind individuals, and screens might all just blend together
  • Made correction samples for different types of colorblindness

Co-op matchmaking QOL

Self-initiative on the topic of QOL improvements, this was something felt by many colleagues playing the game, and also popped up on Reddit occasionally.

Goals

  • In every event, there are missions requiring players to clear a number of co-op events
    • By user anecdotes, also drawn out in data, there is an imbalance between the number of people hosting and people joining
  • Create a new matching option, which allows players to queue as either, making matching faster

Results

  • Working within engineering limitations, made a flow in which players will queue as guests, then after some time of being unable to find a lobby, transition to hosting

Data setup automation

The character event data setup tool referenced above: an Excel/VBA sheet that takes an event ID, its start and end times, the character name, and a reference event to pull global rewards from, then generates the event data in one click.

Goals

  • Data was still manually handled within the team, which was both time-consuming and error-prone
    • The tool was meant to significantly reduce data setup time, allowing more time to focus on new content

Results

  • Tool significantly cut down data setup time, taking a 3-day task down to 0.5 day including manual in-game checks
  • Expanded tool out to all regularly run events

Paper Heroes

Building a mobile gacha game from the ground up. This gave the opportunity to work a lot on creating new features, and developing workflows.

Feature development

Sample design documentation, briefly showing top-level summary of the spec and requirements

  • Worked on development of several game features (4 game modes, 2 economy features)
  • Specified requirements from different departments
    • Art requirements, highlighting any aspects which require animation
    • Programming requirements, specifying which parts are to be set in data, and what loc-keys/data-ids to use
  • Data structure setup and data export setup

Workflow tools for prototyping

  • With development and iteration, speed is crucial, and when programming resources are limited, some workarounds are needed
  • Lacking a visual editor for map creation, developed a map editor in Excel that would allow designers to make their own maps
    • Included an export tool that would read the map data and put it into output data for programmers

A/B testing

Using A/B tests was important for trying to guide the direction of the game, especially with conflicting opinions; data would ground out decisions.

  • Established separate Excel files for the A/B test
  • Worked with programmers on ironing out requirements, what data to target, and the remote config to use
  • Set up A/B testing using Firebase
    • Set remote config, percent of user base
    • Ran test and confirmed that players were being served different versions

Parallel

Working with Parallel on their digital card game of the same name, the cards were created by the client, while the digital implementation was handled entirely within Electric Square. This was a collaborative process working with the client to iron out card verbiage and rules.

Card and deck UX

Managed all card-related UX, from initial mock-up to implementation, and further iteration.

  • Deck builder UX
    • UX mock-up for the deck builder
    • Control scheme specifications (inspecting/adding/removing/scrolling)
  • Card UX
    • Card play/targeting UX for every card mechanic
    • Card play flow
    • Card VFX and VFX order

Card rules and implementation management

Owner for all things cards on the implementation end; the largest role for this is identifying the programming and art work required, and ensuring redundant work is not requested.

  • Broke down the rulesets of cards designed in analog
    • Identified unique mechanics needing implementation (deal X damage, deal X damage Y times, deal X damage to random enemy, clone target enemy, etc.)
    • Flagged issues with existing cards
      • Problematic mechanics (infinite loops, exploits, etc.)
      • Unclear rules/inconsistent phrasing (i.e. using different vocab for the same intended action)
      • Major UX issues not identified in analog
  • Spearheaded documentation fixes to the card VFX list, working with the VFX artist to fill in use cases and card examples for each VFX
  • Created and maintained a card versioning document to support the QA workflow

Lords of the Fallen 2

Working with CI Games in Unreal Engine, to create enemies for Lords of the Fallen 2.

Enemy attack design and prototyping

  • Designed and prototyped attacks for 3 enemies, including 1 mini-boss
    • Retargeted existing animations, mixing animations or layering to achieve the desired result
    • Used existing VFX and modified them to fit new projectiles/AOEs
  • Worked with animators, prioritizing more unique animation work first, while using placeholders for other attacks

Enemy behavior trees

  • Set up behavior trees for new enemies
    • Outlined attack, pacing, block/evade, and reposition behavior
    • Set up special interactions (i.e. taunts on player death)
  • Implemented EQS and custom Behavior Tree Tasks to customize enemy behaviors

Custom Blueprint behaviors

  • Worked in Blueprints to build out behaviors not handled by the existing system
    • Attacks that need pathfinding
    • Weapon throws needing to switch out a held weapon with a projectile
    • Other special abilities
  • Built custom nodes for VFX to hook up the start/loop/end of VFX

Animation tweaking/prototyping

  • Adjusted poses to improve readability of attacks
  • Tweaked weapon animations, especially for large weapons which could hide the enemy's silhouette
  • Set up attack tracking, hit frames, and parry frames
    • Set frame times for windup, anticipation, read, hit, follow, stay, and recovery
